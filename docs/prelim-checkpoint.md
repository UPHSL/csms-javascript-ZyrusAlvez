## My T03 Implementation

The SQLite database is stored at `data/csms.db` by default, configured through `src/database/connection.js` which provides an `openDatabase()` function and I created it to have a default path so we don't have to specify its path everytime we use it making the `connection.js` to solely handle the db connection on its own. The `ResidentRepository` class in `src/repositories/ResidentRepository.js` handles all Resident persistence including it's creation of table. When `save()` is called, it executes a parameterized INSERT statement that stores the Resident's information into the `residents` table. The Resident ID is generated by SQLite through `INTEGER PRIMARY KEY AUTOINCREMENT`, and after insertion, the generated ID is obtained from `result.lastInsertRowid`. The repository then calls `findById()` with that ID to return the complete Resident. `findById()` executes a SELECT query with the given ID and converts the database row back into a Resident instance using `toResident()`. If no record is found, `findById()` returns `null`.


## My Persistence Design Decision

I decided to place the table initialization inside `ResidentRepository` rather than in `connection.js` because I wat the `connection.js` to only handle about the connection and nothing else while the `ResidentRepository` is the class that entirely handles the `residents` table and its columns.


## My Database Initialization Design

- Database initialization file or module: `src/repositories/ResidentRepository.js`
- Where the database path comes from: `src/database/connection.js` defaults to `data/csms.db`, but accepts an optional `dbPath` parameter to override it
- How the Resident table is initialized: The constructor calls `initialize()`, which runs `CREATE TABLE IF NOT EXISTS residents (...)` with all required columns
- How repeated initialization is handled: `CREATE TABLE IF NOT EXISTS` ensures the statement is safe to run multiple times without destroying existing data or creating duplicate tables

I designed it this way because the repository owns the table. The connection module should not need to know which tables exist. This separation keeps each file focused on one responsibility.

## SQL I Can Explain

```sql
INSERT INTO residents (first_name, last_name, address, contact_number, email, status)
VALUES (?, ?, ?, ?, ?, ?)
```

- This statement inserts a new row into the `residents` table with the six provided values.
- Each `?` is a placeholder filled by the prepared statement in order: `resident.firstName`, `resident.lastName`, `resident.address`, `resident.contactNumber`, `resident.email`, `resident.status`.
- The `id` column is omitted so SQLite generates it automatically via `AUTOINCREMENT`.
- This statement is used by the `save()` method in `ResidentRepository`.


## My Resident Mapping

The `toResident()` method converts a SQLite row object into a `Resident` instance by passing the row's values into the `Resident` constructor. The database uses snake_case column names while the JavaScript model uses camelCase property names. For example, the database column `first_name` maps to the Resident property `firstName`, `last_name` maps to `lastName`, and `contact_number` maps to `contactNumber`. The `id`, `address`, `email`, and `status` columns share the same name in both representations.
